# Codex Cloud PowerShell Gallery HTTP 403 Workaround

Codex Cloud currently sets `HTTP_PROXY`/`HTTPS_PROXY` to `http://proxy:8080`. In this environment, the proxy can allow GitHub, NuGet.org, Microsoft package feeds, and .NET bootstrap downloads while returning HTTP 403 for PowerShell Gallery and some Azure Artifacts package blob endpoints.

For local PowerShell source audits in Codex Cloud, use a **core engine build** that avoids the blocked feeds:

```bash
# From this repo root:
./research/scripts/build-powershell-in-codex-cloud.sh
```

The important build flags are:

```powershell
Import-Module ./build.psm1
Start-PSBuild -UseNuGetOrg -NoPSModuleRestore
```

Why these flags are needed:

- `-UseNuGetOrg` keeps core dependency restore on NuGet.org, which is reachable in the observed Codex Cloud proxy environment.
- Pre-restoring `src/powershell-unix`, `src/TypeCatalogGen`, and `src/ResGen` creates the required restore assets without touching `src/Modules`, which is the project that hits PowerShell Gallery.
- `-NoPSModuleRestore` skips `src/Modules/PSGalleryModules.csproj`, avoiding PowerShell Gallery module packages such as `PSReadLine`, `Microsoft.PowerShell.Archive`, `PowerShellGet`, and related gallery-hosted dependencies.
- A full/default build can still fail in this environment because the repo's default PowerShell Azure Artifacts feed may list packages successfully but then return 403 for package blob downloads.
- A full `-UseNuGetOrg` build can still fail because the module restore path uses `https://www.powershellgallery.com/api/v2/`, which returns 403 in affected Codex Cloud sessions.

If the PowerShell repository is already cloned and bootstrapped, the shortest manual sequence is:

```bash
cd upstream/PowerShell

# Undo NuGet config files generated by earlier failed attempts.
git checkout -- nuget.config src/Modules/nuget.config test/tools/Modules/nuget.config 2>/dev/null || true

# Ensure shallow clones can satisfy PowerShell.Common.props' git describe call.
if ! git describe --abbrev=60 --long >/dev/null 2>&1; then
  git tag -fa v7.7.0-preview.3-local -m v7.7.0-preview.3-local HEAD
fi

PATH="$HOME/.dotnet:$PATH" pwsh -NoLogo -NoProfile -Command 'Import-Module ./build.psm1; Switch-PSNugetConfig -Source Public'
dotnet restore ./src/powershell-unix --runtime linux-x64 /property:SDKToUse=Microsoft.NET.Sdk --verbosity quiet
dotnet restore ./src/TypeCatalogGen --runtime linux-x64 /property:SDKToUse=Microsoft.NET.Sdk --verbosity quiet
dotnet restore ./src/ResGen --runtime linux-x64 /property:SDKToUse=Microsoft.NET.Sdk --verbosity quiet
PATH="$HOME/.dotnet:$PATH" pwsh -NoLogo -NoProfile -Command 'Import-Module ./build.psm1; Start-PSBuild -UseNuGetOrg -NoPSModuleRestore'
```

Quick diagnostic commands:

```bash
# Expected in affected Codex Cloud sessions: CONNECT 403.
curl -I --max-time 20 https://www.powershellgallery.com/api/v2/

# Expected to be reachable through the proxy.
curl -I --max-time 20 https://api.nuget.org/v3/index.json
```

If a fully packaged build or Pester suite requires gallery modules, use a different network, a pre-populated NuGet/global module cache, or a vetted local package mirror. Do not submit security reports based only on behavior that depends on this Codex Cloud proxy limitation.
